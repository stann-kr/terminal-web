# 변경 이력

공개 가능한 결과 중심 변경 요약이다. 항목은 일자 단위이며 최신 항목을 위에 둔다.

## 2026-11-13 — 리뷰 후속: 설정·CI 정리와 문구 통일

### Fixed

- 게스트 신청: 이미 이벤트의 대기 명단에 있는 게스트가 다시 대기 신청을 하면(다른 초대인의 마감된 코드 포함) "이미 대기 명단에 있습니다"로 안내한다. 이전에는 방금 입력한 코드의 초대인 이름으로 "대기 명단에 올렸습니다"를 보여 줬지만 실제 명단은 먼저 올린 쪽에만 있었다. 응답에는 `alreadyWaiting: true`가 붙는다.

### Changed

- 화면 문구의 요청 어미를 "주십시오"로 통일했다.
- `wrangler.toml` 맨 위 이름을 `terminal-web-local`로 바꿨다. 맨 위 설정은 로컬 개발만 쓰며, `--env`를 빠뜨린 deploy가 로컬용 설정을 운영 Worker에 올리지 못한다. 배포하는 Worker 이름은 그대로다.
- Worker의 요청 자동 로그(`invocation_logs`)를 껐다. 서명 토큰이 들어 있는 요청 주소가 로그에 남지 않는다. 코드가 남기는 로그는 그대로다.
- `npm run signal:mail`의 회신 주소를 코드에서 지우고 `SIGNAL_REPLY_TO`(환경 변수 또는 `.env`)에서 읽는다. 값이 없거나 메일 주소 하나가 아니면 아무것도 하지 않고 멈춘다.
- CI: PR에서 기준 브랜치에 이미 있는 migration SQL·snapshot이 바뀌지 않았는지 대조한다(`npm run db:check-history -- --base <ref>`). `npm audit`은 push·PR 검증에서 빼고 주간 workflow로 옮겼다.

### Removed

- 쓰이지 않던 `public/og/terminal.png`. 공유 이미지는 `terminal-share.png`다.

## 2026-11-13 — 전체 코드 리뷰: 대기 명단 동의 경계와 운영 스크립트 안전장치

### Fixed

- 게스트 신청: 정원이 찬 코드의 신청은 게스트가 대기 동의문에 동의해 `waitlist: true`를 보낸 경우에만 대기 명단에 올린다. 일반 동의문으로 작성하는 사이 정원이 차면 서버가 409로 거절하고, 화면은 입력을 유지한 채 대기 동의문으로 바꿔 다시 묻는다. 코드가 바뀌어 동의문이 달라지면 이전 동의 체크를 유지하지 않고, 완료 화면은 실제로 보낸 내용만 보여 준다.
- 수신 거부가 구독 행과 함께 같은 주소로 게스트 신청에 남긴 이메일·소식 수신 동의도 지운다.
- 초대 코드 확인이 신청 기간 밖에서는 403 `REQUEST_PERIOD_INACTIVE`로 답한다.
- 아티스트 초대 페이지: 재조회가 한 번 실패해도 마지막으로 읽은 명단과 입력을 유지하고 알림과 다시 불러오기를 보여 준다. 정원이 찬 상태의 표기를 대기 명단 안내와 맞췄고(`FULL · WAITLIST`), 명단이 바뀌어 거절된 등록·올리기 뒤에는 명단을 다시 읽는다. 등록·올리기가 링크 무효로 거절되면 읽어 둔 명단을 바로 내린다. 홍보 자료 목록을 읽지 못해도 명단은 보여 준다.
- 무대: 주소의 쿼리가 경로보다 늦게 반영돼 BACK 카드와 Esc가 틀린 주소를 가리키던 문제, 목록의 범위를 벗어난 쪽 번호 표시(마지막 쪽으로 표시하고 주소는 그대로 둔다), 마지막 쪽에서 다음 쪽 키가 사라질 때 키보드 focus가 사라지던 문제, 모션을 멈춘 화면에서 boot 표식과 떠나는 층이 잘못 보이던 문제를 고쳤다.
- 초대 마감 안내의 일정 구독 키가 앱 내 브라우저에서 조용히 무시되지 않고 세션의 CALENDAR 키와 같게 안내한다.
- 방문자 로그 목록의 같은 초 글 순서를 고정했다.

### Changed

- `npm run transmit:remove`의 `--remote` 삭제·복원은 `--confirm <글 ID>`가 있어야 실행하고 없으면 계획만 출력한다. 복원은 백업을 가져온 곳(운영·로컬)과 대상이 다르면 거부한다.
- `npm run signal:mail`의 발송 로그를 메일 내용(제목·본문)별 파일로 바꾸고 구독자의 signal id만 기록한다. 날짜 이름의 이전 로그는 기본으로 읽지 않으므로 이어서 보낼 때는 `--log`로 지정한다. 로그를 쓸 수 없으면 보내기 전에 멈추고, 보낸 뒤 기록에 실패하면 그 자리에서 멈춰 손으로 추가할 id를 알려 준다.
- `npm run kit`은 매니페스트가 없을 때만 `--init`으로 새로 시작하고 다른 읽기 오류와 매니페스트 형식이 아닌 저장 내용에서는 멈춘다. 이전 매니페스트 보관에 실패하면 덮어쓰지 않는다.
- 운영 스크립트가 `.env` 값의 따옴표를 벗겨 읽고, 실패 메시지에서 이메일 주소를 가린다.
- 아티스트 초대 페이지의 홍보 파일 요청이 명단 조회와 다른 시도 제한 예산을 쓴다.
- CSP에서 쓰지 않는 외부 출처(cdnjs)를 제거했다.
- 문서: 사이트 공유 이미지 경로(`public/og/terminal-share.png`)와 로컬 개발의 원격 D1 바인딩 안내를 실제 구성에 맞췄다.

## 2026-08-23 — Gate capability와 접근성 경계 정리

### Added

- `0000`부터 연속된 SQL, journal tag, snapshot chain과 exact path + SHA-256 lock을 검사하는 migration history guard를 CI에 추가했다.
- Drizzle 생성을 임시 디렉터리에서 검증하고 journal + 다음 SQL + snapshot만 반영한 뒤 lock을 갱신하는 명시적 `db:generate -- --name <safe_name>` wrapper를 추가했다.

### Changed

- Gate의 신청 기간·upcoming event·access-code rule과 D1 atomic repository를 분리하고 Request·code-info route가 같은 domain 판정을 사용하도록 정리했다.
- Gate Request의 지원되지 않던 기타 초대자 입력을 제거하고, 서버가 확인한 아티스트 identity만 읽기 전용으로 표시하도록 변경했다.
- 세 공개 폼의 field error와 첫 오류 focus 계약을 공유하고, 제목이 있는 Terminal panel을 labelled section과 heading으로 렌더링한다.
- Docker build context에서 local env·private 문서·generated output을 제외하고, ESLint·Vitest가 source와 실제 test discovery를 기준으로 실패하도록 설정을 정리했다.
- 사용하지 않는 정적 이벤트 사본·boot context·legacy CRT/accent alias와 과거 텍스트 측정 의존성을 제거했다.
- repository migration history를 `0000`–`0009`의 10개로 정합화하고, `0009`에서 `transmit_logs.created_at`을 지원되는 레거시 값에서 ISO timestamp `TEXT NOT NULL`로 재구성하도록 고정했다. development/production remote apply는 별도 승인·검증으로 유지한다.

### Fixed

- Gate Request와 Signal의 신규·중복 성공 응답을 동일한 `200 { ok: true }`와 `no-store`로 맞춰 제출 결과가 HTTP status로 구분되지 않게 했다.
- `TerminalButton`이 `aria-pressed` 등 native button 속성을 실제 DOM에 전달하도록 수정했다.

## 2026-08-14 — Cloudflare development/production 환경 분리

### Changed

- Wrangler development/production 환경을 고정 Worker와 분리 D1 binding으로 명시하고 build·preview·deploy command가 항상 target environment를 지정하도록 변경했다.
- Cloudflare Workers Builds를 유일한 자동 배포 경로로 정리하고 GitHub Actions는 validation만 담당하도록 경계를 분리했다.
- `dev`는 development Worker, `main`은 production Worker를 대상으로 하며 production deploy와 D1 migration·secret·binding·route 변경은 독립 승인 단계로 유지한다.

## 2026-08-13 — 접근성·공개 API·성능·검증 계층 강화

### Added

- route별 metadata, skip link와 고유 main landmark, Node/jsdom 테스트 project, Next·Worker HTTP smoke, 임시 D1 migration smoke와 secret 없는 validation CI를 추가했다.
- 공개 이벤트/아티스트 runtime decoder, 공통 rate-limit/Turnstile 검증 인터페이스, PII-safe log와 Transmit idempotency 계약을 추가했다.
- Gate와 Lineup 선택 상태를 URL query와 browser history에 동기화했다.

### Changed

- 의미 텍스트는 서버 HTML부터 최종 문자열로 렌더링하고 cipher는 대표 타이틀로 제한했다.
- 전역 WebGL을 Home hero 조건부 dynamic enhancement로 격리하고 Status의 3D realtime 표시는 접근 가능한 정적 레지스트리로 바꿨다.
- Home 이벤트 CTA·semantic directory와 즉시 사용 가능한 intro skip을 추가하고, 근거 없는 build/uptime/realtime 표기를 제거했다.
- 공개 민감 응답을 no-store로 통일하고 게스트 정원 누락을 fail-closed로 처리했다. Signal·Gate 중복 제출은 식별 정보를 노출하지 않는 성공 응답을 사용한다.
- ordinary Docker dev 환경에서 Cloudflare 배포 자격 증명 전달을 제거했다.

### Fixed

- 신청/코드 검증의 loading·invalid·inactive·unavailable 상태를 분리하고 세 공개 폼의 label, field error, live region과 오류 focus를 복구했다.
- reduced-motion/save-data/hidden 상태에서 비필수 timer·scramble·Canvas가 계속 동작하던 문제를 정리했다.

## 2026-08-11 — 공개 API와 런타임 신뢰 경계 정비

### Security

- `use-scramble`의 텍스트 전용 DOM 쓰기 패치를 일반 npm 설치와 Docker 설치 모두에서 적용·검증하도록 고정했다.
- 콘텐츠 보안 정책과 프레이밍 차단 등 기본 보안 응답 헤더를 추가하고 프레임워크 식별 헤더를 제거했다.
- 공개 JSON API가 입력 타입과 허용 필드, 본문 크기를 데이터베이스 접근 전에 검증하도록 강화했다.
- 게스트 신청의 이메일 중복·아티스트별 정원 판정과 선택적 마케팅 등록을 하나의 D1 배치로 처리하도록 고정했다.
- 인증 코드는 URL에 남지 않는 POST 본문으로만 확인하고 응답 캐시를 금지했다.
- 전송 로그 공개 응답과 신규 저장 입력에서 디바이스 식별자를 제외했다.

### Changed

- TypeScript 오류를 무시하던 프로덕션 빌드 설정을 제거했다.
- 로컬 개발과 Docker의 기본 포트를 3005로 통일했다.
- Node 환경의 Vitest 실행 계약을 추가했다.
- 종료 시각이 지난 `UPCOMING` 이벤트를 응답 시점에 보관 상태로 판정하고, 미래 이벤트는 시작 시각순으로 제공한다.

### Fixed

- 동시 구독 요청이 이메일 고유 제약에서 500으로 바뀌던 경쟁 조건을 409 중복 응답으로 안정화했다.
- 인증 코드 연속 입력에서 이전 응답이 최신 입력 상태를 덮어쓸 수 있던 요청 경쟁을 차단했다.
