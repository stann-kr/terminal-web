# 기능 계약

이벤트 발견과 참여 동선을 우선합니다. 머리글·바닥글·메뉴 없이 화면 전체가 무대이고, 판 일곱 개(다음 이벤트 · 이벤트 · 아티스트 · 인스타그램 · 소식 신청 · 방문자 로그 · 소개)가 메뉴를 대신합니다. 주소가 화면을 정하고, 지금 보는 판이 아닌 판은 판 전체가 그 화면으로 가는 링크입니다. 홈이 아닌 화면에는 직전 화면으로 돌아가는 BACK 카드가 있으며 Esc도 같습니다. 인스타그램 판은 화면 없이 공식 계정을 새 탭(폰에서는 앱)으로 엽니다.

홈은 가장 가까운 미래 UPCOMING → LIVE → 최근 ARCHIVED 순으로 대표 행사를 선택합니다. 예정 행사가 없어도 지난 행사 기록을 제공합니다. 조회 실패와 데이터 없음은 구별합니다. 없는 이벤트·아티스트 주소는 404로 응답하고, 무대는 부모 판을 열어 그 안에 알림으로 보여 줍니다. 이벤트를 읽지 못한 경우는 404가 아니라 다시 불러오기를 제공합니다.

아티스트는 공개 상태 CONFIRMED·ARCHIVED만 노출합니다. 출연 행 ID는 전역 인물 ID가 아닙니다. `features/artists/identities.ts`의 검토된 매핑만 인물을 합치고, 미확정 출연은 별도 기록으로 유지합니다. 사라지거나 비공개가 된 행은 프로필에서 제외합니다. 명부와 프로필에는 참여 횟수·최근/첫 출연 요약·연도 집계를 표시하지 않으며, 이름·출신·소개와 개별 출연 기록에 집중합니다.

행사 상세는 공개 공연표와 원문 소개를 제공합니다. 무대 표기는 공간 위치가 아니며 TBA를 실제 시간으로 추정하지 않습니다. 이벤트는 시작부터 끝까지 진행 중(LIVE)이고 끝나면 기록(ARCHIVED)입니다. 끝은 데이터의 `endTime` 또는 모든 공개 슬롯에 시간이 있을 때 마지막 슬롯의 끝이며, 둘 다 없으면 시작과 함께 기록이 됩니다. 진행 중에는 공연표에서 시간표상 지금 순서를 "시간표 기준"으로 표시하며 실제 재생 상태로 표현하지 않습니다. 포스터는 실제 URL이 있을 때만 표시합니다. 이벤트는 LIVE → 시작 시각순 UPCOMING → 최신순 ARCHIVED를 한 카드 목록에 표시하며, 목록 페이지는 URL에 보존합니다. 별도 행사 기록 화면은 없고 기존 `/archive`는 `/events`로, `/events?selected=...`는 해당 상세 주소로 연결합니다.

게스트 신청은 가장 가까운 미래 UPCOMING 행사 한 건에서 시작 30일 전부터 시작 직전까지 열립니다. 코드 확인 뒤 연락처와 동의를 받으며, 코드 변경은 이전 확인을 무효화합니다. 서버 행사 불일치는 자동 재제출하지 않습니다. 저장 성공은 입장 확정이나 티켓 발급을 의미하지 않습니다.

Signal은 연락처 저장만 제공합니다. 인증 이메일, 발송, 수신 거부 API가 구현된 것처럼 표현하지 않습니다. 개인정보·마케팅 동의의 목적과 보존 기간 원문을 유지합니다.

Transmit은 공개 닉네임과 280자 메시지, 서버 기준 5건 pagination을 제공합니다. 같은 요청의 네트워크 재시도에는 같은 Idempotency-Key를 사용합니다. 전송 중 수정한 초안은 저장 응답 후에도 유지합니다. 서버가 반환한 공개 글을 확인한 뒤에만 성공으로 표시합니다. 운영자는 공개 로그의 글을 백업한 뒤 내리고 그 백업으로 되돌릴 수 있습니다.

공개 쓰기(초대 코드 확인·게스트 신청·소식 신청·방문자 로그)는 접속 주소·작업별 시도 제한을 받고, 넘으면 잠시 뒤 다시 시도하라고 안내합니다.

세션 상세는 일정 구독(CALENDAR) · 지도(MAP, 지난 이벤트 제외) · 주소 공유(SHARE)를 제공합니다. 검색엔진에는 운영 주소만 열고, sitemap과 이벤트 구조화 데이터에는 기록에 있는 사실만 담습니다(끝 시각·라인업·포스터는 있을 때만).

가짜 관객 수, 실시간 재생 상태, 판매량, QR, 결제, 로그인, 아티스트 SNS·사진을 임의로 만들지 않습니다.
